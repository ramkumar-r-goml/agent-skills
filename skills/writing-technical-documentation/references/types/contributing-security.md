# CONTRIBUTING and SECURITY

CONTRIBUTING: how to set up, run tests (including the single-test form), style and commit conventions, branch and PR process, review expectations, and how to propose large changes. Read CI config for what actually gates a merge, since that outranks anything an old document says.

SECURITY: supported versions, how to report a vulnerability privately, what happens next, and the disclosure policy. Do not invent contact addresses, response times, or supported versions. Ask, or mark `[unverified: ...]`, because a false promise in a security policy is worse than none.
